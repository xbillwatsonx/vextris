# Draft GitHub Issue — Mobile touch controls

**Title:** `feat: add touch-first mobile controls and high-score entry`

## What and why

Vextris was playable in a phone-sized viewport but required a hardware keyboard. This feature makes the complete game loop playable on a coarse-pointer portrait device: move and drop pieces, rotate, select and cast Vex spells, pause, mute, and enter high-score initials.

The aim is clear, explicit controls rather than gesture-only play. That keeps the game discoverable and avoids accidental actions during fast play.

## Scope

- A state-scoped mobile HUD and two-row touch dock during playing/paused states.
- Pointer-safe held movement alongside existing keyboard DAS/ARR behavior.
- Touch, click, keyboard, and accessibility state wiring for one-shot actions.
- A touch-only A–Z / Backspace / Confirm initials keypad.
- Mobile-specific instructions while retaining desktop keyboard instructions.
- Viewport-fit layout for common portrait phone sizes, including safe-area handling.
- Tests, release-candidate documentation, templates, and CI.

## Acceptance criteria

- [ ] A player can complete normal gameplay on a phone without a hardware keyboard.
- [ ] Move, soft drop, hard drop, both rotations, cycle, cast, pause, and mute work through touch.
- [ ] Held touch movement safely clears on cancellation, blur, loss of pointer capture, and backgrounding.
- [ ] High-score initials can be entered through an on-screen keypad.
- [ ] Desktop keyboard controls and layout remain usable.
- [ ] Board, HUD, and dock fit together without page scrolling at 375×667 (safe-area), 390×740, 390×812, and 390×844.
- [ ] Full tests, lint, and production build pass.

## Constraints

- Do not introduce gesture-only controls.
- Keep desktop behavior and keyboard controls intact.
- Touch controls only appear for coarse-pointer portrait play and the relevant game states.
- No deployment, release, or public GitHub action is included in this issue.
