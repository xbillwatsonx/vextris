# Draft PR — `feat: mobile touch controls`

## Summary

Adds a touch-first mobile experience to Vextris, preparing **v0.3.0** as a release candidate. The desktop keyboard game remains intact; coarse-pointer portrait play gets a compact status HUD, an explicit two-row touch dock, mobile instructions, and an on-screen initials keypad.

## Motivation

The existing game could visually fit on a phone but was keyboard-only. This change makes normal play, spell use, pause/mute, and high-score initials entry possible without a hardware keyboard.

## Linked issue

`Closes #<issue-number>`

## Major implementation details

- Introduces shared `GameAction` dispatch so keyboard and touch one-shot actions use the same game behavior.
- Adds pointer-ID-owned held movement; keyboard and touch inputs are unioned so releasing one does not cancel the other.
- Adds accessible Pointer Events and click wiring, with concurrent one-shot protection and pressed-state cleanup.
- Uses a state-scoped `is-mobile-gameplay` body class so desktop and overlay presentation stay separate from live mobile gameplay.
- Adds mobile HUD state synchronization for Pause/Resume and Mute/Unmute, including `aria-pressed`.
- Adds a touch A–Z / Backspace / Confirm high-score keypad and extracts pure initials transitions for test coverage.
- Replaces the desktop instruction copy with touch-specific instructions on coarse-pointer portrait devices.

## Accessibility behavior

- Semantic `<button>` controls have descriptive labels.
- Click and Pointer Events are both supported without duplicate activation.
- Pause/mute labels and `aria-pressed` values remain synchronized.
- Controls use a minimum 48px height and suppress text selection and iOS callouts.
- Keyboard support remains available on desktop.

## Known limitations

- Mobile presentation is designed for coarse-pointer portrait play, not landscape phone play.
- No gesture-only mode is provided by design; the dock favors discoverability.
- Automated screenshots use Chrome emulation. Real-phone testing was manual and did not include a recorded device/browser matrix.
- The v0.3.0 version bump, tag, GitHub Pages deployment, and GitHub repository settings are deliberately not included in this PR candidate.
